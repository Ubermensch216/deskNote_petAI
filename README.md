# DeskNote

Windows 로컬 AI 스티키 위젯. 제품 정의는
[기획 보고서](docs/Windows%20로컬%20AI%20스티키%20위젯%20제품·기술%20기획%20보고서.pdf)를 따른다.

핵심 원칙은 보고서 p21의 우선순위다: **메모 → 기억 → AI → 자동화**.
AI는 어느 단계에서도 메모 앱의 필수 의존성이 되지 않는다. 모델을 받지 않아도 메모 기능은
100% 동작하고, 모델을 지워도 데이터는 온전하다.

## 프로젝트 구조

| 프로젝트 | 대상 | 역할 |
|---|---|---|
| `src/DeskNote.Core` | net10.0 | 도메인 모델, 인터페이스, UI·DB에 의존하지 않는 정책 |
| `src/DeskNote.Data` | net10.0 | SQLite + FTS5, 마이그레이션, 리포지토리 |
| `src/DeskNote.App` | net10.0-windows | WinUI 3 데스크톱 UI (실행 진입점) |
| `tests/DeskNote.Core.Tests` | net10.0 | 도메인·배치·자동저장 정책 |
| `tests/DeskNote.Data.Tests` | net10.0 | 영속성, 한국어 FTS, 마이그레이션 |
| `tests/DeskNote.Benchmarks` | net10.0 | SLO 측정과 강제 종료 내성 검증 (콘솔 실행 파일) |

의존 방향은 `App → Core ← Data`. `Core`는 아무것도 참조하지 않는다.
AI 계층은 `Core`의 `ILocalAiService` 뒤에만 존재한다. 지금은 인터페이스와 항상 "사용 불가"를
반환하는 `NullAiService`, 그리고 결과 타입(`Ai/`)까지만 있고 앱에 주입된 구현은 없다.

## 빌드와 실행

```bash
dotnet build
```

```bash
dotnet run --project src/DeskNote.App
```

Visual Studio는 필요 없다. WinUI 3의 XAML 컴파일러와 Windows SDK 빌드 도구는 NuGet에서 온다.
앱은 unpackaged + Windows App SDK self-contained로 빌드되므로 별도 런타임 설치도 필요 없다.

## 테스트

```bash
dotnet test
```

xunit.v3 는 Microsoft.Testing.Platform 러너를 직접 호스팅하고 .NET 10 SDK 는 VSTest 로 그것을 실행하지
않는다. 그래서 `global.json` 의 `test.runner` 로 러너를 지정해 둔다 — 이 항목이 없으면 `dotnet test` 는
바로 오류로 끝난다. 현재 `Core` 268개와 `Data` 72개, 340개 테스트가 모두 통과한다.

## 메모 모양

쉬고 있는 노트에는 아무 조작 요소도 보이지 않는다. 화면에 있는 것은 글과 그 글이 놓인 종이뿐이고,
포인터가 올라오거나 키보드 포커스가 들어오면 그때 조작 요소가 페이드인한다 (보고서 p4). 자리는 미리
잡아 두므로 나타났다 사라질 때 본문이 다시 흐르지 않는다.

| 위치 | 내용 |
|---|---|
| 위쪽 | `+` 새 메모 · `⋯` 메뉴 · `✕` 닫기, 그 사이는 창을 끄는 손잡이 |
| 아래쪽 | 굵게 · 기울임 · 밑줄 · 취소선 · 글머리 목록 · 체크리스트 · 이미지 |
| `⋯` 메뉴 | 색상 8종 · 불투명도 · 항상 위 · 크기 · 알림 · 메모 라이브러리 · 삭제 |

색상·불투명도·항상 위·크기는 모두 노트마다 저장되므로 다시 켜도 그대로 뜬다. 불투명도에는
하한(`Note.MinOpacity`)이 있어 노트를 완전히 투명하게 만들어 잃어버리는 일은 없다. 아래쪽 서식
막대의 명령은 전부 위의 단축키와 같은 것이며, 막대는 그것을 찾을 수 있게 하고 단축키는 빠르게 한다.

제목 칸은 없다. 스티커 메모는 빈 창에 떠오른 생각을 적는 자리라 제목 칸은 거의 언제나 비어 있고,
240×180 노트에서 그 한 줄은 비싸다. 제목은 본문의 첫 줄에서 만들어지며(`NoteContent.DeriveTitle`),
`# 회의 준비` 는 `회의 준비` 가 된다 — 마크업은 그 줄이 무슨 말인지가 아니라 어떻게 보이는지다.

`⋯` 메뉴의 `✦` 줄은 AI 자리이며 지금은 비활성이다. 로컬 모델이 없으면 누를 것도 없다는 사실을 UI에서
그대로 보여주는 편이, 눌렀을 때 실패하는 버튼보다 낫다.

## 메모 라이브러리

노트의 `⋯` 메뉴에서 **메모 라이브러리 / Notes Explorer** 를 연다. 전체 메모를 노트북·태그·삭제
여부로 좁혀 보고, 검색창에 입력하면 150ms 뒤 FTS 검색이 돈다. 행을 한 번 누르면 해당 메모가
바탕화면에 뜬다.

**삭제됨** 범위에서는 행을 고르고 **복원 / Restore** 를 누른다. 삭제는 소프트 삭제이므로 되돌릴 수 있다.
왼쪽의 **새 노트북** 으로 노트북을 만든다.

태그는 본문 안의 `#backend` 처럼 쓴 해시태그가 원본이고, `tags`/`note_tags` 테이블은 저장 시
본문에서 다시 만들어지는 조회용 투영이다. Markdown 제목(`# 제목`)과 구분하기 위해 `#` 바로 뒤에
공백이나 `#` 이 오면 태그로 보지 않는다.

## 알림

노트의 `⋯` → **알림 / Remind me** 에서 10분 뒤·1시간 뒤·내일 아침 9시를 고른다. 30초마다
확인하므로 절전/최대 절전에서 깨어난 뒤에도 놓치지 않는다. 반복 알림은 RFC 5545 `RRULE` 의
부분집합(`FREQ=DAILY|WEEKLY|MONTHLY|YEARLY`, `INTERVAL`)을 쓰며, 자리를 비운 사이 지나간 반복은
하나로 합쳐 다음 회차만 알린다.

## 첨부

이미지를 붙여넣으면 메모 폴더로 복사되고, 파일을 끌어다 놓으면 10MB 이하 이미지만 복사하고
나머지는 원본 위치를 링크한다 (보고서 p5: 대용량은 복사보다 링크 우선). 서식 막대의 이미지 단추는
파일 선택 대화상자를 열어 같은 경로를 탄다 — 붙여넣기와 끌어다 놓기는 빠르지만 어느 쪽도 눈에 보이지
않는다. 어느 쪽이든 본문에는 Markdown 참조가 삽입되므로 `Ctrl+Z` 로 되돌릴 수 있다.

종료를 제공한다. 마지막 메모를 닫아도 여기로 돌아올 수 있다.

## 언어

## 로컬 AI

AI는 [Ollama](https://ollama.com)를 통해 로컬에서만 돈다. `ILocalAiService` 뒤의 구현이
`src/DeskNote.Ai`의 `OllamaAiService`이고, 인터페이스가 요구하는 "모델은 별도 프로세스에서"
격리는 Ollama 자체가 별도 프로세스라 그대로 충족된다. 데몬이 죽으면 HTTP 호출이 실패해 AI가
"사용 불가"로 내려갈 뿐, 메모 창은 아무 영향도 받지 않는다.

```bash
ollama pull gemma4:e2b
```

| 설정 키 | 기본값 | 뜻 |
|---|---|---|
| `ai.enabled` | (없음 = 켬) | `false` 면 소켓조차 열지 않는다 |
| `ai.endpoint` | `http://localhost:11434` | 로컬 추론 서버 주소 |
| `ai.model` | `gemma4:e2b` | 텍스트 동작에 쓰는 모델 |
| `ai.embeddingModel` | `bge-m3:latest` | 검색 임베딩용 모델 (의미 검색 도입 시) |

값이 깨져 있으면 기본값으로 되돌아간다. AI 설정을 잘못 써서 앱이 못 뜨는 일은 없다.

가용성 확인(`/api/tags`)은 메모가 화면에 뜬 뒤 백그라운드에서 시작하고 1분마다 다시 확인한다.
가중치는 이 경로에서 절대 로드하지 않는다 (보고서 p14: "앱 시작 = 모델 시작" 금지).

메모 본문은 **데이터이지 지시가 아니다**. 본문·선택 영역·제목은 언제나 시스템 프롬프트가 아니라
사용자 메시지의 `<UNTRUSTED_NOTE_CONTEXT>` 블록 안에 들어가고, 본문이 그 구분자를 흉내 내면
지워진다 (보고서 p16). 할 일 추출과 태그 제안은 JSON 스키마로 디코딩을 강제한 뒤 한 번 더
검증한다 — 읽을 수 없는 날짜는 추측하지 않고 버린다 (보고서 p11).

i7 / 16GB CPU 추론에서 gemma4:e2b 기준 요약 약 25초, 할 일 추출 약 45초가 걸린다. 모델이 메모리에
올라가 있지 않은 첫 호출은 7.2GB를 읽어 들이느라 60초에 가깝다. 모든 동작은 취소 가능하고,
결과는 적용 전까지 메모에 쓰이지 않는다.

### 쓰는 법

노트의 `⋯` 메뉴 아래쪽 **AI** 구역에서 고른다. 텍스트를 선택해 두면 그 부분만, 선택이 없으면
메모 전체가 대상이다.

| 칩 | 동작 |
|---|---|
| 요약 / 정리 | 핵심만 남기기 / 제목·목록·체크박스로 구조화 |
| 간결 · 격식 · 친근 · 보고서 | 같은 내용을 그 어조로 다시 쓰기 |

누르면 미리보기 창이 **먼저** 뜨고 (CPU에서 수십 초가 걸리므로 기다리는 중임을 보여준다),
끝나면 원본과 제안을 나란히 보여준다. **적용**을 눌러야 본문이 바뀌고, 그 편집은 일반 편집과
똑같이 `Ctrl+Z` 로 되돌아가며 리비전으로 남는다. 창을 닫으면 추론이 취소된다.

모델이 답하는 동안 메모를 고쳤다면, 적용 대상 구간이 더 이상 같지 않으므로 적용을 거부하고
그 사실을 알린다 — 사용자가 방금 쓴 문장을 오래된 제안으로 덮어쓰지 않는다.

AI가 준비되지 않았으면 칩이 비활성화되고 그 자리에 이유가 표시된다 (모델 없음 / 서버 미실행 /
꺼짐). 준비됐으면 모델 이름과 실행 위치(CPU·GPU)가 같은 자리에 표시된다.

### 할 일 추출과 태그 제안

같은 AI 구역의 `할 일` · `태그` 는 본문을 고쳐 쓰는 대신 **목록을 제안**한다. 모델은 세 개는 맞히고
하나는 틀릴 수 있으므로, 항목마다 체크박스가 따로 붙는다. 기본은 전부 선택돼 있고, 적용은 선택한
것만 반영한다.

- 할 일 → 본문 끝에 `- [ ] 제목` 으로 붙는다. 마감이 있으면 그 시각에 이 메모의 알림이 걸린다.
  마감·담당·중요도는 확인 목록에서 보여 주되 본문 줄에는 넣지 않는다 — 본문은 사용자의 문장이다.
- 태그 → 본문 끝에 `#태그` 로 붙는다. 이미 달려 있는 태그는 제안 목록에서 빠진다.

뽑아낼 것이 없으면 빈 목록 대신 "제안할 것이 없습니다" 라고 말한다. 마감이 적히지 않은 할 일에
날짜를 지어내지 않는 것과 같은 이유다.

### 메모 Q&A

`Ctrl+Space` (또는 AI 구역의 `질문`) 로 사이드카를 연다. 마지막으로 쓰던 메모가 있으면 그 메모만
근거로 답하고, 없으면 FTS 검색으로 관련 메모를 찾아 답한다 — 어느 쪽인지 창 위에 적혀 있다.
답은 토큰이 오는 대로 흘러나오고, 창을 닫으면 추론이 취소된다. 이 창은 메모를 고치지 않는다.

`Ctrl+Space` 는 **`ai.enabled` 가 꺼져 있지 않을 때만** 등록한다. 한국어 IME도 원하는 조합이라,
호출할 것이 없는 상태에서 시스템 전역으로 뺏지 않는다.

### 의미 검색 (하이브리드 검색)

Q&A가 메모를 고를 때 키워드 검색과 의미 검색을 함께 돌린다. 둘은 서로 다른 방식으로 실패한다 —
FTS는 "페이먼트 모듈 논의"라고 적힌 메모를 "결제 관련 회의"로 찾지 못하고(겹치는 단어가 없다),
임베딩은 주문번호처럼 질문 문장으로 옮기기 어려운 내용을 놓친다. 실측:

```
Q: "결제 시스템은 언제 손보기로 했어?"   (메모 본문: "페이먼트 모듈 리팩터링을 3분기에")
FTS 결과 0건 · 벡터 결과 1건 → 융합 결과 1건
```

순위 융합은 RRF(Reciprocal Rank Fusion)를 쓴다. FTS5 rank는 음수 BM25이고 벡터는 코사인이라
같은 축에서 비교할 수 없지만 순위는 비교할 수 있다. 양쪽 모두에서 나온 메모가 한쪽에서만 나온
메모를 이긴다 — 하이브리드를 쓰는 이유가 그것이다.

| 조각 | 위치 |
|---|---|
| 청킹 (빈 줄 기준, 500자, 80자 겹침) | `Core/Services/NoteChunker.cs` |
| 순위 융합 | `Core/Services/RankFusion.cs` |
| 임베딩 호출 (`/api/embed`) | `Ai/OllamaEmbeddingService.cs` |
| 벡터 저장·검색 | `Data/SqliteVectorIndex.cs` (`002_embeddings.sql`) |
| 저장 뒤 색인 | `App/Services/EmbeddingIndexer.cs` |
| 키워드+의미 결합 | `App/Services/HybridRetriever.cs` |

보고서(p8)는 sqlite-vec을 지목하면서 같은 문단에서 pre-v1이라 파괴적 변경 가능성을 경고한다.
그래서 실제로 넣은 건 **평범한 SQLite 테이블에 float32 BLOB을 넣고 코사인을 in-process로 도는
브루트포스**다. 아키텍처별 네이티브 확장을 싣고 업그레이드마다 재검증하는 비용이, 수천 개 벡터를
몇 밀리초에 훑는 이득보다 크다. `IVectorIndex` 뒤에 있으므로 그 비용이 정당해지는 날 바뀌는 파일은
`SqliteVectorIndex.cs` 하나다.

임베딩은 **저장의 결과이지 저장의 일부가 아니다**. 저장은 그대로 30ms 안에 끝나고
(보고서 p13), 벡터는 잠시 뒤 따라온다. 임베딩 모델이 없으면 아무 오류도 내지 않고 그 메모가 의미
검색에서 빠질 뿐이다. 같은 메모를 연달아 고치면 큐에서 하나로 합쳐진다.

모델 이름이 행마다 저장되므로, `ai.embeddingModel` 을 바꾸면 이전 모델의 벡터는 비교 대상에서
빠지고 "아직 색인 안 됨"으로 취급돼 다시 만들어진다. 서로 다른 모델의 벡터를 섞어 비교하는 일은
없다. 시작할 때마다 색인이 없는 메모를 25개씩 따라잡는다.

bge-m3는 1024차원이고, 질문 하나를 임베딩하는 데 약 0.3초가 걸린다(모델이 올라가 있을 때).

## 저장과 버전

타이핑이 멈추고 300ms 뒤에 저장이 시작된다(보고서 p5의 250–500ms 대역 중간). 노트마다 타이머가
따로 있어 한 노트에서 치는 동안 다른 노트의 저장이 밀리지 않고, 창이 포커스를 잃거나 닫히거나 앱이
끝날 때는 디바운스를 무시하고 먼저 쓴다.

덮어쓰기 전의 본문은 `note_revisions` 에 남는다. 평범한 타이핑은 5분 간격으로만 체크포인트를
남기고, 본문을 통째로 바꾸는 동작(복구, 일괄 치환, 나중의 AI 동작)은 항상 먼저 스냅샷을 뜬다.
노트당 50개까지 유지한다. 되돌리기 UI는 아직 없고, 지금은 기록만 쌓인다.

`%LOCALAPPDATA%\DeskNote\notes.db` (WAL). 로그는 `%LOCALAPPDATA%\DeskNote\logs\desknote.log`.

손상 위험이 있어, 동기화는 이후 note-level operation 복제로 구현한다 (보고서 p6).
