# 게임성 분석 검토 및 구현 계획

작성일: 2026-09-17 · 검토 기준: 로컬 체크아웃 `b7a0237`

진행 상태: 1차 기능 구현과 자동 검증을 완료했다. 실제 변경 및 남은 검증은
[1차 구현 결과](gameplay-stage1-progress.ko.md)를 참고한다. 아래 본문은 최초 계획이다.

## 1. 결론

첨부 보고서의 핵심 제안인 **기존 성장 규칙을 유지하면서 기억·발견·꾸미기 보상을 추가하는 방향**을 채택한다. 첫 출시에서는 **미션 완료 → 기억 카드 획득 → 앨범에 축적 → 성장에 따라 새로운 반응 해금**을 완성한다. 사용처 없는 재화, 상점, 제작부터 만들지 않는다.

우선순위는 보고서와 일부 다르게 잡는다. 성격은 기존 카운터를 활용할 수 있지만 분류 안정성·전용 대사·행동이 필요하므로 두 번째 단계로 옮긴다. 미니게임은 세 종류 동시 구현 대신 공 던지기 한 종류로 검증한다. 방은 20~30개 아이템보다 고정 슬롯과 6~8개 장식으로 시작한다.

이번 작업은 첨부와 소스·설계문서·테스트·CI 구성에 대한 정적 검토 및 구현 계획 수립이다. 제품 코드를 변경하거나 빌드·플레이테스트를 실행하지 않았다. 경쟁 제품의 최신 기능과 흥행 인과관계는 별도로 검증하지 않았으며, 이를 채택 근거로 단정하지 않는다.

추가로 해결해야 할 세 가지가 있다.

1. **미션의 달성 가능성:** `DailyMissionPlanner`는 AI 적용을 포함한 앱 활동을 날짜로 선택한다. AI 미설정 사용자, 오래된 메모가 없는 신규 사용자에게 완료 보상을 사실상 제한할 수 있다. 욕구가 충족된 펫은 지정된 먹이·놀이 돌봄을 바로 수행할 수도 없다.
2. **집계 범위 불일치:** `CountRewardedTodayAsync`의 앱 상한은 프로필 전체에 적용되지만 `ReadDailyProgressAsync`는 앱·돌봄 모두 선택 펫으로 필터링한다. 펫 전환 후 이미 소진된 앱 활동이 미션 화면에는 미완료로 보일 수 있다.
3. **재시도와 버전 변경:** 앱 이벤트에는 고유 ID가 있지만 `CareRequest`에는 요청 ID가 없다. 메타 보상에 단순히 `(source_event_id, rule_version)`만 복제하면 정책 버전 변경 시 같은 업적을 다시 지급할 수 있다. 지급 정체성과 계산 버전을 분리해야 한다.

## 3. 유지할 제품 원칙

- 기존 XP·돌봄일·용 해금 조건·종별 점수 공정성을 유지한다.
- 결석 페널티, 연속 출석 강제, 펫의 죄책감 유발 대사, 기간 종료 시 보상 몰수는 넣지 않는다.
- AI는 표현만 담당한다. 자격 판정·보상·성격 계산은 결정적 코드가 담당한다.
- 메모 저장 이후 companion 처리를 수행하는 기존 실패 경계를 유지한다.
- 포커스를 빼앗지 않는다. 조용한 시간·발표/집중 상태·동작 끄기·키보드 접근을 신규 UI에도 적용한다.
- 메모 원문·제목·AI 답변을 보상 원장과 기본 기억 카드에 복제하지 않는다.

## 4. 1차 출시: 기억이 남는 일일 루프

### A. 보상 전에 미션 규칙과 집계를 정리

권장 기본안은 **인정된 앱 활동 중 아무 종류 1개 + 서로 다른 돌봄 2종**이다. 날짜별 특정 활동은 선택적 추천으로 남기고, 보상 조건에는 AI나 특정 욕구를 강제하지 않는다. 특별 돌봄·인사·재우기가 있어 욕구 감소를 기다리지 않고도 돌봄 두 종류를 완료할 수 있다.

보상 미션 진행은 프로필의 로컬 날짜 단위로 앱·돌봄 원장을 합산한다. 기존 선택 펫의 성장·욕구·돌봄 횟수 표시와 구분하여 `MissionProgress`를 별도로 제공한다. 돌봄 2종은 펫이 달라도 서로 다른 행동 종류여야 한다. 지급은 프로필당 날짜별 1회로 제한한다. 카드에는 완료를 일으킨 이벤트의 펫을 기록하며, 펫을 바꿔도 완료와 지급 상태가 유지된다.

### B. 오늘의 기억 카드 자동 지급

- 완료 순간 XP 대신 날짜·펫·테마가 담긴 카드 1장을 자동 지급한다. 별도 수령 버튼은 두지 않는다.
- 대시보드에 완료 표시, 카드 미리보기, 앨범 열기 동작을 제공한다.
- 재실행·연타·펫 전환·동일 이벤트 재처리에도 카드는 중복되지 않는다.
- 첫 출시에는 소비 재화를 넣지 않는다. 나중에 장식을 추가할 때 앨범 누적 수와 단계로 직접 해금한다. 재화가 필요해지는 시점에 지급·소비 원장을 함께 설계한다.
- 같은 테마가 반복되어도 날짜별 추억으로 남기되, “모든 카드 수집”에 무작위 확률이나 기간 한정을 강제하지 않는다.

### C. 기억 앨범

첫 콘텐츠는 미션 완료·단계 성장·메모 재활용·체크리스트 완료 등 템플릿 8~12개로 제한한다. 이벤트가 증명하는 사실만 쓰고, 원문 없이 “함께 메모를 다시 살펴본 날”처럼 표현한다. 일반 행동 카드는 하루 1장까지, 미션·단계 카드는 별도 고유 키로 관리한다. 정확한 수량은 플레이테스트에서 조정한다.

카드는 `template_id + template_version + occurred_at + local_date + pet_kind` 및 허용된 최소 파라미터를 저장한다. ko/en 렌더링을 지원하고, 언어를 바꿔도 의미와 날짜가 유지된다. 메모 링크는 기본 범위에서 제외한다. 향후 링크를 제공하면 삭제된 메모로 이동할 수 없도록 nullable 참조와 UI 처리를 함께 구현한다.

목록은 최신순 페이지 조회, 날짜·펫 필터를 제공한다. 텍스트를 대량 이미지로 생성하지 않고 기존 펫 에셋과 카드 UI를 사용한다.

### D. 단계업의 체감 강화

2~5단계마다 새 반응 또는 소품·대사 묶음 하나를 해금한다. 예: 2단계 특별 인사, 3단계 종별 소품, 4단계 휴식 반응, 5단계 축하 반응과 대표 카드. 기존 성장 표식은 단계 식별용으로 유지한다.

성장 전후 차이를 저장 계층에서 판정하고 `CompanionUnlockCatalog`로 단계별 콘텐츠를 결정한다. UI의 스냅샷 차이만으로 지급하지 않는다. 처음 열거나 펫을 전환할 때 이미 보유한 단계를 새로운 성장으로 오인해서는 안 된다. 기존 사용자에게는 현재 단계까지 콘텐츠를 해금하되, 알 수 없는 과거 성장 날짜를 만들어 내지 않고 “업데이트 시 보유 단계” 카드 한 장으로 안내한다.

첫 출시 완료 기준: AI 없이 미션 달성 가능, 완료 카드 자동 저장, 재실행 후 앨범 유지, 성장 해금 확인, XP 규칙 불변, 중복 지급 없음.

## 5. 후속 기능의 순서

| 순서 | 범위 | 구현 방식 및 완료 기준 |
|---|---|---|
| 2차 A | 성격 표현 | `CompanionPersonalityProjector`로 호기심/통찰/신뢰 비율 계산. 표본 부족은 “알아가는 중”, 동률은 균형형. 최소 표본·우세 격차·전환 완충 규칙을 테스트로 고정. 성격별 대사와 기존 자세 선택 확률을 연결하고 XP 효율은 동일하게 유지 |
| 2차 B | 공 던지기 1종 | 별도 WinUI 화면에서 10~30초 조작. 키보드 방식과 간편 놀이 제공. 실력·실패 횟수로 XP 차등 지급하지 않음. 끝나면 기존 돌봄 정책을 통해 한 번 처리 |
| 3차 A | 방과 장식 | 벽·바닥·가구 3개 고정 슬롯, 장식 6~8개. 앨범/성장 해금 → 즉시 배치 → 재시작 후 유지. 자유 좌표 편집·충돌 판정·상점 제외 |
| 3차 B | 취향과 주간 목표 | 종 기본 취향 + 최초 확정 후 유지되는 개체 취향. 좋아함은 반응 차이만 제공. 주간 목표는 5개 중 3개, 연속일·놓친 주 페널티 없음. 이전 주 보상 소급·주 경계 규칙을 명시 |
| 4차 | 완전체 마스터리·도감 | XP 상한을 억지로 늘리기보다 누적 관계 기록에 반응·대사·장식 해금. 완전체 펫을 계속 선택할 이유 제공 |
| 검증 후 | 제작·나머지 미니게임·시즌 콘텐츠 | 실제 수집·배치 사용성과 콘텐츠 제작 비용을 확인한 뒤 확대. 시즌 종료 후에도 획득 경로 유지 |
| 별도 선택 기능 | 로컬 AI 회고 | 기본 템플릿이 항상 작동하고, 명시적으로 선택한 문맥만 로컬 AI에 제공. 실패·시간 초과 시 템플릿 사용. 저장·삭제·재생성 범위를 함께 설계 |

성격의 평생 합계는 초반 이력이 강하게 남고 각 활동의 일일 상한도 다르다. 단순 최댓값만으로 즉시 성격을 고정하지 않는다. 초기에는 기존 합계를 이용하되, 실제 분포를 확인한 후 최근 기간 보조 지표가 필요한지 판단한다. 기존 돌봄에 신뢰를 추가하는 변경은 별도의 밸런스 결정으로 남긴다.

미니게임에는 `session_id`, 시작 시 `pet_kind`, 시작/종료 시각, 완료 여부가 필요하다. 도중 종료에는 보상 없음, 완료 콜백 재진입에는 중복 없음, 펫 전환 후 다른 펫에 지급하지 않도록 한다. 시작 때 자격을 안내하고 완료 시 다시 검사한다. 상한을 이미 소진해도 연습 플레이는 허용하며 보상 여부를 미리 표시한다. 같은 놀이를 반복했을 때 기본 점수가 지급될 수 있는 현재 `CarePolicy`와 UI의 제한도 이 단계에서 정합성을 맞춘다.

### 첫 마이그레이션의 최소 테이블

- `companion_meta_reward_ledger`: 프로필, `grant_key`, 보상 종류, 지급 정책 버전, 원인 이벤트 ID, 발생 시각, 로컬 날짜, 귀속 펫.
- `companion_memory_album`: 카드 ID, 지급 원장 참조, 템플릿 ID/버전, 표현에 필요한 최소 데이터. 지급 원장 참조에 고유 제약을 두어 카드 중복 방지.
- `companion_unlocks`: 프로필·펫·콘텐츠 키·해금 시각. 같은 콘텐츠 재해금 방지. 프로필 공용 항목은 NULL의 UNIQUE 동작에 의존하지 않는 명시적 scope 키 사용.

방·인벤토리·주간 진행 테이블은 해당 기능을 구현할 때 추가한다. 보상 원장은 컬렉션의 지급 기록이며, 1차에서는 가상 화폐 잔고를 관리하지 않는다.

지급 키 예시는 `daily-mission:2026-09-17`, `stage:Cat:3`, `memory-event:<source-id>:recall`이다. `UNIQUE(profile_id, grant_key)`가 지급 정체성을 보호하고 정책 버전은 감사용 필드로 남긴다. 규칙 버전을 올렸다는 이유로 기존 카드나 장식을 다시 지급하지 않는다.

### 처리 흐름과 복구

1. 기존 앱 이벤트 또는 돌봄 요청을 검증한다. 원장 삽입과 성장 갱신은 기존 규칙을 따른다.
2. 동일 SQLite 트랜잭션에서 해당 날짜의 프로필 미션, 대상 펫의 단계 변화와 콘텐츠 조건을 판정한다.
3. 지급 원장·카드·해금을 함께 저장하고 커밋한다. 실패하면 companion 작업 전체가 롤백된다. 이미 성공한 메모 저장에는 영향이 없다.
4. 커밋 이후 UI에 결과를 알린다. 연출이 누락되어도 카드가 남아 있어 앨범에서 확인할 수 있다.

앱 큐는 현재 bounded channel/DropOldest 방식이며 영구 재처리 큐가 아니다. 따라서 “모든 사용자 활동을 반드시 추억으로 남긴다”는 보장은 하지 않는다. 이미 원장에 저장된 이벤트의 중복 방지·복구와, 큐에만 있다가 사라진 이벤트의 유실은 구분한다. 완전한 활동 보장이 필요해질 때 outbox를 별도 설계한다.

지연 처리된 이벤트는 처리 시점이 아니라 저장된 이벤트 날짜의 미션으로 판정한다. 돌봄 재시도에는 요청 ID를 추가하고 원장 고유 제약으로 방어한다. 펫 귀속도 UI 요청/이벤트 발행 시 캡처하는 방향으로 정리하여 큐 대기 중 선택이 바뀌어도 일관되게 유지한다.

시계 되돌리기로 이미 받은 날짜의 보상을 다시 받지는 못한다. 다만 오프라인 로컬 앱에서 미래 시각 조작을 완벽히 막을 수 있다고 주장하지 않는다. 시간 변경으로 기존 보상을 회수하거나 사용자를 벌주지 않는다.

기존 DB는 `MigrationRunner`의 백업 경로를 사용한다. 기존 성장 기록을 다시 계산하거나 축소하지 않는다. 과거 전체 미션은 일괄 보상하지 않고 활성화 날짜 이후만 대상으로 한다. 업데이트 당일 기존 인정 기록은 집계하여 첫 reconcile에서 1회 지급할 수 있도록 한다. 이전 버전 앱 실행 시 신규 데이터 유지와 이후 재진입 동작은 별도 호환성 시험 대상으로 둔다.

## 7. 작업 분할과 예상 규모

아래는 구현·기본 검증을 포함한 **1인 작업일의 초기 추정**이며 확정 일정이 아니다. 신규 원화 제작, 장기간 플레이테스트 대기, 배포 운영은 제외한다. 첫 작업에서 실제 UI 결합도와 DB 시험 결과를 보고 재산정한다.

| 작업 | 산출물 | 선행 조건 | 예상 |
|---|---|---|---:|
| 0 | 미션/펫/날짜/지급 계약 확정, UI 연결부 부분 추출 | 없음 | 2~3일 |
| 1 | 프로필 미션 집계, 메타 정책, 006 마이그레이션, 원장/해금·재시도 처리 | 0 | 3~5일 |
| 2 | 기억 앨범, 템플릿 8~12개, 자동 지급과 ko/en UI | 1 | 3~5일 |
| 3 | 단계별 콘텐츠 4묶음, 기존 사용자 해금, 접근성·출시 회귀 검증 | 2 | 3~5일 |
| 4 | 성격 분류와 대사/행동 연결 | 3 | 3~5일 |
| 5 | 공 던지기, 세션 중복 방지, 간편/키보드 경로 | 3 | 4~7일 |
| 6 | 고정 슬롯 방, 장식 6~8개, 저장/배치 검증 | 3 | 5~8일 |

첫 출시 범위는 작업 0~3으로 약 **11~18작업일**이다. 이후 1~2주 실사용 관찰을 거쳐 4~6의 순서와 규모를 조정한다. 주간 목표·제작·시즌팩·AI 회고는 이 시점에 별도 견적을 낸다.

## 8. 검증과 출시 판단

자동 검증:

- Core: XP 30/70·성장 조건 회귀, 미션 대체 행동, 같은 날짜 결정성, 동률/표본 부족 성격, 콘텐츠 ID·ko/en 누락.
- Data: 앱 행동이 마지막인 경우와 돌봄이 마지막인 경우 모두 지급; 동시 요청·재시도·재시작·정책 버전 변경에도 정확히 한 번 지급.
- 경계: 자정 전후와 지연 이벤트, 시간대 변경, 펫 전환, 기존 단계 1~5 마이그레이션, 여러 단계 해금, 메타 저장 실패 시 원자적 롤백.
- 개인정보: 카드에 제목·본문·AI 출력이 들어가지 않음. 향후 메모 링크 도입 시 삭제 동작 추가 시험.
- 통합: 기존 companion/Data 테스트에 필요한 사례를 추가하고 CI 전체의 format/build/test/10,000-note 성능/패키징을 실행.

수동 검증:

- 새 사용자·AI 미설정·짧은 PC 사용 시간에서도 첫 미션을 이해하고 완료할 수 있는가.
- 완료 후 무엇을 받았는지 보이고, 다음 실행에서도 앨범을 찾을 수 있는가.
- 모션 끄기·조용한 시간·발표/집중 상태에서 방해하지 않고, 키보드·스크린 리더로 이용 가능한가.
- 7종, 작은 펫 크기, 밝은/어두운 테마, ko/en에서 반응·카드·소품이 잘리지 않는가.
- 펫 비활성화 상태에서 기존 메모 기능과 성능이 유지되는가.

성공 기준은 클릭 수나 매일 접속 강제가 아니다. 첫 사용자가 보상을 설명할 수 있는지, 앨범을 다시 열어볼 이유가 있는지, 기존보다 방해가 늘지 않았는지를 관찰한다. 초기에는 동의한 소규모 사용자 인터뷰와 로컬 진단으로 확인하며 원격 행동 수집을 기본 도입하지 않는다.
